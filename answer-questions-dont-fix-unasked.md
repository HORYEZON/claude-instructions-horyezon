# Questions get answers, not unasked fixes

When the owner asks a how-to or info question (steps, a link, an explanation), **answer it**. Don't edit code, push, redeploy or file release notes on the side. If checking turns up a bug, report it with the evidence and **ask** whether to fix it.

**Why:** on 10/13/26 the owner asked only for Sharing Debugger steps. A found font bug was then fixed and shipped unasked: code, push, redeploy, draft note. The owner had to ask what had been done.

**How to apply:**
- The per-task delivery workflow covers tasks the owner gives, not fixes discovered while answering.
- A rejected tool call means stop and ask.
- An ambiguous "Please Continue" after a rejection does not approve the rejected change.
